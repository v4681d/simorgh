# Contributing to Simorgh

Thanks for helping! This project is small and friendly — open an issue first
for anything non-trivial so we can agree on direction.

## Development setup

```sh
pnpm install --dir ui
cargo install tauri-cli --version '^2' --locked
cargo tauri dev
```

Linux system deps: `libwebkit2gtk-4.1-dev libgtk-3-dev libasound2-dev
libayatana-appindicator3-dev librsvg2-dev libssl-dev`.

Or use the container: `docker build -f docker/Dockerfile.build -t simorgh-build .`

## Before you push

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
pnpm --dir ui build
```

CI enforces all of the above plus `cargo-deny` (licenses, advisories).

## What makes a good PR here

- **Engine adapters** — implement one trait, register one factory line, add a
  UI catalog entry. Read [docs/adding-engines.md](docs/adding-engines.md)
  first; the partials/finals contract and the `self_generated` TTS flag are
  load-bearing.
- **Locales** — add `ui/src/locales/<lang>.json` and register it in
  `ui/src/i18n.ts`. RTL languages: set direction handling like `fa`.
- **Tests** — engines must be testable offline; use mock engines and recorded
  fixtures. Gate real-API tests behind env vars.
- **Commits** — conventional commits (`feat:`, `fix:`, `docs:`…) please; the
  changelog is generated by git-cliff.

## Code style

- Rust: rustfmt defaults, clippy clean, `thiserror` for typed errors. Every
  user-facing error should carry an actionable `fix` hint.
- No secrets in config or code — API keys go through the OS keychain.
- UI: Tailwind with the design tokens in `ui/tailwind.config.js`; keep the
  mockup (`docs/design/simorgh-ui.html`) as the visual source of truth.
